# Расширение `MCP_Сервер`: работа через публикацию

Расширение поднимает MCP-сервер **внутри информационной базы**: HTTP-сервис принимает
JSON-RPC 2.0 и выполняет вызовы кодом 1С. Одна и та же публикация даёт одинаковый набор
инструментов в любой базе, где стоит расширение, — скилл от базы не зависит, меняется
только адрес публикации и учётка.

Глубокий контракт конкретной базы (состав объектов, исходники расширения, ограничения
по коду) — в KB проекта, если он там есть: страница сервиса `mcp-server`
(`docs/services/mcp-server/tools.md`). Искать — `skill://kb-search/gitmark.py search
"MCP_Сервер"`; страницы может не быть — тогда опирайся на разделы ниже и на
`tools/list` самой базы.

## Подключение

| Адрес | Метод | Что |
|---|---|---|
| `http://<host>:<port>/<ИмяБазы>/hs/mcp/rpc` | POST | JSON-RPC 2.0 — вся работа |
| `http://<host>:<port>/<ИмяБазы>/hs/mcp/health` | GET | `{"status":"ok"}` |
| `http://<host>:<port>/<ИмяБазы>/hs/mcp/*` | POST | streamable HTTP (то же ядро) |

- Имя публикации в URL — **регистрозависимо**: несовпадение даёт редирект, а редирект
  превращает POST в GET.
- Аутентификация — Basic с учёткой информационной базы. Учётку брать из локального
  конфига проекта (`v8project.local.yaml`, ключ `infobase.connection`, поля `Usr`/`Pwd`).
- **Пароль не передавать аргументом командной строки** — он виден в `ps`. Читать креды
  внутри процесса (пример ниже) или через переменную окружения; сам файл целиком не
  печатать — там же лежат и другие значения.
- Первым делом — проверка подключения; разбор ответов в разделе «Проверка перед работой».

Рабочий каркас вызова (креды не покидают процесс):

```python
import re, json, base64, urllib.request
cfg = open('v8project.local.yaml', encoding='utf-8').read()
user, pwd = re.search(r'Usr="([^"]*)";\s*Pwd="([^"]*)"', cfg).groups()
BASE = 'http://<host>:<port>/<ИмяБазы>/hs/mcp'
auth = base64.b64encode(f'{user}:{pwd}'.encode()).decode()

def rpc(method, params=None, rid=1, timeout=120):
    body = json.dumps({'jsonrpc': '2.0', 'id': rid, 'method': method, 'params': params or {}}).encode()
    req = urllib.request.Request(BASE + '/rpc', data=body, method='POST')
    req.add_header('Authorization', 'Basic ' + auth)
    req.add_header('Content-Type', 'application/json')
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read().decode())

def tool(name, args):
    res = rpc('tools/call', {'name': name, 'arguments': args})['result']
    return res.get('isError'), ''.join(c.get('text', '') for c in res.get('content') or [])
```

Порядок: `initialize` → `tools/list` → `tools/call`. `protocolVersion` сервера —
`2025-03-26`; в `serverInfo` — версия расширения.

## Проверка перед работой

Первый вызов — `GET <публикация>/hs/mcp/health`. Ответ однозначно говорит, что не так,
и гадать по нему не нужно:

| Ответ | Что это значит | Что делать |
|---|---|---|
| `200` + `{"status":"ok"}` | публикация есть, расширение в базе, доступ разрешён | работать |
| `401` + заголовок `WWW-Authenticate: Basic realm="1C:Enterprise 8.3"` | публикация есть, аутентификация не прошла | проверить учётку ИБ |
| `404`, тело — **HTML веб-сервера** (`<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">`) | **публикации нет**: базы нет по этому адресу либо не совпал регистр имени | проверить адрес и регистр; публикует базу оператор |
| `404` с **пустым телом** (ответ 1С) | база опубликована, но HTTP-сервиса `mcp` в ней нет: расширение не установлено, выключено или неактивно | проверить наличие и активность расширения (ниже) |
| `405` | сервис есть, но не тот шаблон или метод: `/rpc` принимает только POST, `/health` — только GET | поправить адрес |
| соединение отклонено или таймаут | веб-сервер не слушает этот адрес/порт | уточнить адрес публикации у оператора |

**Если MCP не отвечает — как проверить, что расширение вообще есть в базе:**

- файловая ИБ: `ibcmd extension --db-path=<каталог ИБ> list` — покажет состав расширений
  и признак `active`; на базе с пользователями может потребовать учётную запись;
- серверная ИБ: только конфигуратор, диалог «Расширения конфигурации» — это операция
  оператора, агент её не выполняет.

**Расширение может быть установлено, но выключено** — тогда сервиса тоже нет, и ответ
будет тем же `404` с пустым телом. Признак активности виден там же: `ibcmd` — колонка
`active`, конфигуратор — флажок активности.

**Чего делать не нужно:** если расширения в базе нет или публикации нет — через MCP
задача не решается вообще. Нужны две операции оператора: загрузить `MCP_Сервер.cfe` в
базу и опубликовать HTTP-сервис на веб-сервере (у каждой базы публикация своя). Сказать
об этом прямо, а не искать обходные пути и не подменять инструмент конфигуратором.

## Инструменты

| Инструмент | Назначение | Обязательные параметры |
|---|---|---|
| `execute_query` | запрос 1С → JSON или CSV | `query` |
| `validate_query` | проверка синтаксиса запроса без выполнения | `query` |
| `execute_code` | произвольный код 1С на сервере, результат — `__Возврат` | `code` |
| `list_metadata_objects` | список объектов метаданных по типу и маске | `metaType` |
| `get_metadata_structure` | структура объекта: поля, ТЧ, владельцы, движения | `metaType`, `name` |
| `eventlog_query` | записи журнала регистрации с фильтрами | — |
| `eventlog_filter_values` | допустимые значения фильтров журнала | `field` |
| `storage_reader` | чтение хранилищ настроек платформы | `action`, `storageType` |
| `set_storage_value` | **запись** значения в хранилище настроек | `storageType`, `objectName`, `settingsKey`, `value`, `valueType` |

Плюс ресурс `1csyntax` (`file://resource/syntax_1c.txt` — шпаргалка по встроенному языку,
полезна как контекст при написании кода для `execute_code`) и промпт `explore_storage`.

## Проверенные особенности

- **`eventlog_query`: колонки запрашиваются английскими именами, приходят русскими** —
  в ответе ключи `Дата`, `Уровень`, `ПредставлениеСобытия`, `Комментарий`. Допустимые
  имена колонок и уровней перечислены в тексте ошибки, если ошибиться. Без `from`/`to`
  возвращаются последние `limit` записей (умолчание 50, потолок 500).
- **`list_metadata_objects`**: `nameMask` — подстрока имени **или** синонима, без учёта
  регистра (не регулярное выражение). `maxItems: 0` вернёт **один** элемент, а не всё.
- **`execute_query`**: `maxRows` (умолчание 1000) режет результат **после** выгрузки —
  тяжёлый запрос всё равно выполнится целиком. Параметров в запросе быть не должно:
  значения подставлять прямо в текст. `format`: `json` | `csv`.
- **`execute_code`**: результат — переменная `__Возврат` (инициализирована `Неопределено`).
  Структуру создавать **строкой ключей**: `Новый Структура("а,б", 1, 2)`; лишние значения
  сверх числа ключей молча игнорируются. Коллекции (Структура, Соответствие, Массив,
  ТаблицаЗначений, ДеревоЗначений, СписокЗначений) сериализуются в JSON; `Неопределено`
  → `null`, дата → ISO; прочие типы → `Строка(Значение)`.
- **`storage_reader`**: разделы хранилища перечислить нельзя — `objectName` надо знать
  заранее (`get_list` без него вернёт `reason: ObjectNameRequired`). `path` — ровно один
  уровень вложенности. `limit`/`offset` работают только для табличных значений, в ответе
  `total`/`offset`/`limit`/`returned`/`hasMore`. `format`: `auto` | `json` | `markdown` |
  `schema`. `get_description` у стандартных хранилищ не отдаёт дату и признак сжатия.
- **`set_storage_value`**: принимает только примитивы; вложенные структуры отклоняются с
  `reason: UnsupportedComplexType` (в ответе — готовый BSL-фрагмент для `execute_code`).
  **Удаления в инструментах нет** — за собой убирать кодом:
  `ХранилищеОбщихНастроек.Удалить("<КлючОбъекта>", "<КлючНастроек>", Неопределено)` —
  третий параметр обязателен, иначе «Недостаточно фактических параметров».

## Ошибки: три разных вида

| Что | Как выглядит |
|---|---|
| Ошибка внутри инструмента | `result.isError = true`, текст «Ошибка выполнения инструмента '<имя>': …» |
| Бизнес-ошибка хранилища | `result.isError = false`, в JSON `success: false` + `reason` (`InvalidStorageType`, `ObjectNameRequired`, `PathNotFound`, `UserNotFound`, …) |
| Несуществующий инструмент / метод | **JSON-RPC `error`**, а не `result`: `-32603` для неизвестного инструмента, `-32601` для метода, `-32700` для битого JSON, `-32600` для версии не `2.0` |

Прочее по протоколу: уведомление без `id` → HTTP 204 с пустым телом; `GET` на `/rpc`,
`/mcp` и `POST` на `/health` → 405.

## Ограничения и безопасность

- **Привилегированного режима в расширении нет** — все инструменты работают с правами
  пользователя, под которым аутентифицирован HTTP-сеанс. Это и есть граница доступа.
- Схема параметров **не валидируется сервером**: `required`/`default`/`enum` в
  `tools/list` — подсказка клиенту.
- Требование «спроси пользователя» у `execute_code` и `set_storage_value` — **только
  текст в описании инструмента**, механизма подтверждения нет.
- `execute_code` выполняет произвольный код 1С, включая изменение данных. Перед запуском
  кода с побочными эффектами — явное подтверждение оператора; по умолчанию писать
  только читающий код.
- `set_storage_value` пишет в хранилище настроек, в том числе другому пользователю
  (проверяется лишь его существование в ИБ). Тестовые записи убирать за собой.
- Таймаутов и ограничения размера ответа на пути инструментов нет — большие выборки
  ограничивать самому (`maxRows`, `limit`, `ПЕРВЫЕ N` в запросе).
