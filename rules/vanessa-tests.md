# Vanessa-тесты: только по документации (факап #12 тикета 09)

В Unica НЕТ документации по Vanessa — только по платформе и стандартам.
Единственный источник правды по шагам, структуре фич и API Vanessa —
официальная документация:

**https://pr-mex.github.io/vanessa-automation/dev/**

В тикете 09 агент написал непроверенный шаг `Я вижу элемент с именем`
«по памяти» — такого шага в библиотеке нет.

## Правило

ПЕРЕД созданием или правкой `.feature`-файла:

1. **Существующие шаги** — открыть и прочитать `Шаблон фичи.feature`
   и уже существующие фичи (`features/*.feature`): какие шаги реально
   используются в проекте.
2. **Документация Vanessa** — для любого шага, которого нет в шаблонах,
   проверить его существование в официальной доке:
   `https://pr-mex.github.io/vanessa-automation/dev/` (раздел по шагам /
   библиотеке шагов). Читать через `read` по URL.
3. Только после подтверждения, что шаг существует, — писать его в фичу.

## Навигация по таблицам и выбор значений (факапы B1/B2 тикета 10)

ПЕРЕД написанием шага навигации по таблице или выбора значения:

1. **Заголовки колонок** — Vanessa матчит колонки по `Title` (заголовку),
   а не по имени. Проверить точный `Title` колонок в `Form.xml`:
   ```
   unica.form.info { "metadataPath": "<адрес формы>", "cwd": "<корень>" }
   ```
   Особое внимание: буква «ё» в заголовке (колонка «Партнёр» с «ё» —
   два падения на одном месте). Заголовки подчиняются стандартам
   (см. `rule://standards-check`).
2. **Поведение поля** — перед шагом выбора значения проверить фактическое
   поведение поля: выпадающий список, кнопка выбора (`AutoChoice`),
   таблица. Не предполагать «кнопку выбора», если поле — список.
   Источник: `Form.xml` (`unica.form.info`) + демо-данные ИБ.
3. **Демо-данные ИБ** — точные значения (имена организаций и т.п.) брать
   из фактических данных ИБ, а не диктовать/угадывать.

## Детерминированный слой

Хук `doc-gate.ts` блокирует `write` на `*.feature`, если в сессии не
было ни одной сверки (чтение доки Vanessa или существующих фич/шаблонов).

## MUST NOT

- Писать шаги Vanessa «по памяти» или по аналогии с другими фреймворками.
- Придумывать имена шагов, не проверив их в шаблонах проекта или доке.
- Коммитить фичу с непроверенными шагами.

## Шаги-клики и фикстуры: знания раунда приёмки 1 (проверено 2026-09-06)

1. **Клик по гиперссылке ячейки таблицы не автоматизируется.** Шаг
   `я нажимаю на гиперссылку с именем "X"` существует (без префикса
   `в таблице "Y"` — имена полей колонок уникальны), но его реализация
   (`ВОткрытойФормеЯНажимаюНаГиперссылкуСЗаголовком` → `Нажать()`) на поле
   колонки получает «Невидимый пользователю элемент управления…» — поле колонки
   видимо только на активной ячейке, `я активизирую поле с именем` не помогает.
   Приёмку гиперссылок в таблицах закрывать ручной проверкой живого клиента,
   не шагом Vanessa.
2. **Где смотреть реализацию шагов.** `.epf` бинарен (grep не работает).
   Источник — GitHub `Pr-Mex/vanessa-automation`: интерактивные шаги —
   `VanessaAutomation/Forms/УправляемаяФорма/Ext/Form/Module.bsl`, клиентские
   (клики, поиск элемента) — `Forms/КлиентТестирования/Ext/Form/Module.bsl`,
   реестр частых шагов — шаблон `ЧастоИспользуемыеШаги`. Искать текстом шага
   через GitHub code search.
3. **`Тогда открылось окно "..."`** — проверять по имени элемента фикстуры с
   wildcard (`"*<Префикс>_BDD_…_"*`), не по автогенерному представлению каталога.
4. **Фикстуры — через YAxUnit-хелперы.** Сценарий не создаёт данные сам:
   `И я выполняю код встроенного языка на сервере без контекста
   """ ТестыХХХ.Обеспечить…(); """`; уборка — финальный сценарий
   `Удалить…()`. Уборка обязана быть идемпотентной и полной: все объекты
   обеспечения (включая второстепенные — группы, контрагентов) удаляются и в
   `УдалитьФикстуру…`, чтобы падение сценария не оставляло мусора в ИБ.
5. **Переименование реквизита/элемента формы = правка фич.** Имя поля
   (`у поля с именем "X"`, `из выпадающего списка с именем "X"`) — часть
   контракта: синхронно менять во всех `features/*.feature`.
6. **Формат файлов:** `.feature` — LF, модули `.bsl` — CRLF; скриптовые
   правки фич должны это учитывать (иначе якоря не матчатся).
7. **Прогон:** правка только фич не требует загрузки расширений —
   `"$V8R" test va --no-build`. После полной пересборки `Тесты` — перепрогон
   обеих приёмок. Истинная приёмка — статусы шагов в
   `build/out/cucumber/CucumberJson.json` (все `passed`), строки
   `[error:test_report] Error: 0 (0%)` — шум парсинга статуса Vanessa.

## Ожидание формирования отчёта (знание раунда приёмки 6, 2026-09-09)

Ждать окончания формирования — шагом `Дано Ожидаем завершения фонового
формирования отчета в течение "60" секунд` (#2284, VA ≥ 1.2.042.47; менеджер
и клиент в одной ИБ). Ожидание по координате ячейки (`заполнится ячейка
"R4C1"`) в иерархическом выводе недоказуемо: первая строка данных — групповая
или детальная с пустым полем группы (на проде — детальная строка соглашения
без организации, `R4C1` пуста всегда). Шага «жду когда в табличном документе
появится значение» в VA нет — «Не найдена процедура» (три падения, тикет 18).
Содержательную проверку делает `содержит значения` — он ищет по всем ячейкам
документа, к раскладке не привязан.
