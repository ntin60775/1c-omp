# Форматирование BSL: табы, пробелы и пустые строки

Этот файл — канонический источник истины для `1c-bsl-code-style`, когда
задача затрагивает табы, пробелы, пустые строки или `cleanup whitespace` в BSL.

## Когда читать

- при любой BSL-правке, где меняются табы, пробелы или пустые строки;
- при style-review, где нужно проверить единообразный регистр служебных слов в
  изменяемом коде;
- при `style-cleanup`, который похож на массовую чистку `whitespace`;
- при review или verify-pass, если нужно проверить пустые строки внутри
  `Процедура` / `Функция`.

## Каноническое правило

### `tab-rhythm` — это отдельный formatting-layer

- Правило табов внутри метода отвечает за визуальную геометрию блока в IDE, а
  не за семантику промежуточных переменных, вынесение литералов или пошаговую
  декомпозицию выражений.
- Если обсуждается, на каком уровне должны стоять sibling-операторы, пустые
  строки и тело вложенного `Если` / `Для` / `Пока`, это formatting-layer.
- Если обсуждается, нужно ли вводить `ПривилегированныйРежим`,
  `ПакетныйЗапрос` или другую именованную переменную, это уже другой
  semantic-layer и он не должен подменять правило табов.

### Регистр логических операторов — тоже часть локальной formatting-формы

- В изменяемом BSL-коде логические операторы пишутся как `Не`, `И`, `Или`.
- Формы `НЕ` и `ИЛИ` в коде считаются локальной style-ошибкой, даже если
  платформа их понимает.
- Для этого навыка такое исправление считается детерминированным auto-fix,
  если оно не затрагивает строковые литералы, комментарии с цитатами и другой
  машинно-значимый текст.
- Это правило относится именно к BSL-коду, а не к обычному русскоязычному
  тексту документации.

Менее удачно:

```bsl
Если НЕ ПравоДоступа ИЛИ ОшибкаПроверки Тогда
	РезультатПроверки = Ложь;
КонецЕсли;
```

Лучше:

```bsl
Если Не ПравоДоступа Или ОшибкаПроверки Тогда
	РезультатПроверки = Ложь;
КонецЕсли;
```

### Визуальная геометрия блока в IDE

- Внутри `Процедура` / `Функция` каждый BSL-блок читается как визуально
  непрерывная область на направляющих IDE.
- Все непустые sibling-строки одного логического уровня внутри блока стоят на
  одном и том же tab-уровне.
- Переход в тело вложенного блока добавляет ровно один таб.
- Возврат из вложенного блока снимает ровно один таб.
- Пустая строка внутри блока принадлежит текущему уровню блока и сохраняет его
  tab-уровень, а не превращается в отсутствие отступа.
- Следующая непустая строка после пустой строки возвращается на фактический
  уровень текущего блока и не получает лишний таб.
- Пустая строка перед `ИначеЕсли`, `Иначе`, `Исключение`, `КонецЕсли`,
  `КонецЦикла`, `КонецПопытки` после последнего оператора ветки сохраняет
  tab-уровень тела этой ветки, а не уровень закрывающего ключевого слова.
- Пустая строка перед `КонецПроцедуры` / `КонецФункции` внутри метода сохраняет
  один таб уровня тела метода.
- Такие табы нельзя автоматически удалять как обычный `trailing whitespace`.

### Минимальные инварианты

- Минимальный отступ пустой строки внутри тела метода — один таб.
- Если пустая строка находится внутри тела вложенного блока (`Если`, `Для`,
  `Пока`, `Попытка` и т.п.), она сохраняет отступ тела этого блока: таб метода
  плюс табы вложенности.
- Управляющие блоки `Если`, `Для`, `Пока`, `Попытка` и подобные отделяются
  одной пустой строкой от предшествующих линейных операторов, присваиваний и
  вызовов на том же уровне. Связь строк данных не отменяет это разделение.
- Соседние управляющие блоки одного уровня отделяются одной пустой строкой.
- Если первым оператором внутри тела управляющего блока является вложенный
  управляющий блок, перед ним нужна одна пустая строка на tab-уровне тела
  внешнего блока.
- После открывающей строки ветки `Если ... Тогда`, `ИначеЕсли ... Тогда`,
  `Иначе`, `Попытка`, `Исключение` первое действие по умолчанию отделяется
  одной пустой строкой на уровне тела ветки, если это не однострочный
  микро-блок. Правило действует на любом уровне вложенности, а не только для
  верхней ветки метода.
- Нельзя нормализовать пустые строки внутри метода к меньшему отступу, чем
  ожидает редактор 1С.
- Нельзя исправлять только часть строк блока, если после этого ломается общий
  `tab-rhythm` и визуальная непрерывность уровня в IDE.

## Границы применения

- Это правило относится к табам и пустым строкам внутри тела метода и внутри
  вложенных BSL-блоков.
- Оно задаёт визуальную геометрию блока, но не диктует, нужно ли вводить
  промежуточные переменные или как семантически дробить выражение.
- Оно не требует искусственно добавлять табы в пустые строки между верхнеуровневыми
  объявлениями, где тело метода еще не началось.
- Если задача не про форматирование всего модуля, держите минимальный diff и не
  нормализуйте несвязанные пустые строки ради косметики.

## Визуальная нотация для примеров

- `<TAB>` — табуляция на иначе пустой строке.
- `<EMPTY>` — полностью пустая строка без табуляции.

## Пример

Плохо:

```text
Процедура Пример()
<TAB>Если Условие Тогда
<TAB><TAB>Действие();
<EMPTY>
<TAB>КонецЕсли;
<EMPTY>
КонецПроцедуры
```

Правильно:

```text
Процедура Пример()
<TAB>Если Условие Тогда
<TAB><TAB>Действие();
<TAB><TAB>
<TAB>КонецЕсли;
<TAB>
КонецПроцедуры
```

Отдельно проверяйте пустую строку перед `Иначе`, `ИначеЕсли` и `Исключение`:
она должна оставаться на уровне тела ветки, из которой происходит переход.

## Пример со следующей строкой после пустой

Плохо:

```text
<TAB><TAB><TAB><TAB>СуммаДолг = СуммаДолг + ВыборкаДетали.СуммаДолг;
<TAB><TAB><TAB><TAB><TAB>
<TAB><TAB><TAB><TAB><TAB>ВнешнийИдентификаторПартнера = ...
<TAB><TAB><TAB><TAB><TAB>ВнешнийИдентификаторДоговораСтроки = ...
```

Правильно:

```text
<TAB><TAB><TAB><TAB>СуммаДолг = СуммаДолг + ВыборкаДетали.СуммаДолг;
<TAB><TAB><TAB><TAB>
<TAB><TAB><TAB><TAB>ВнешнийИдентификаторПартнера = ...
<TAB><TAB><TAB><TAB>ВнешнийИдентификаторДоговораСтроки = ...
```

Иначе пустая строка начинает вести себя как ложная вложенность, хотя
реальный уровень блока не менялся.

## Пустая строка после открытия ветки

Менее удачно:

```text
<TAB>Если ЗначениеЗаполнено(РезультатПоиска.Объект) Тогда
<TAB><TAB>ВозвращаемоеЗначение = РезультатПоиска.Объект;
```

Лучше:

```text
<TAB>Если ЗначениеЗаполнено(РезультатПоиска.Объект) Тогда
<TAB><TAB>
<TAB><TAB>ВозвращаемоеЗначение = РезультатПоиска.Объект;
```

Это правило относится к локальной геометрии ветки, а не к семантической
декомпозиции метода.

## Пустые строки вокруг управляющих блоков

Управляющий блок начинается как отдельная визуальная область. Перед ним нужна
пустая строка на уровне текущего тела, даже если предыдущие строки готовят
данные именно для этого условия, цикла или попытки.

Плохо:

```text
<TAB>Контрагент = Объект.Контрагент;
<TAB>Договор = Объект.Договор;
<TAB>Если ЗначениеЗаполнено(Договор) Тогда
<TAB><TAB>
<TAB><TAB>ЗаполнитьДоговор(Договор);
<TAB>КонецЕсли;
<TAB>Попытка
<TAB><TAB>
<TAB><TAB>ЗаписатьОбъект(Объект);
<TAB>Исключение
<TAB><TAB>
<TAB><TAB>Сообщить(ОписаниеОшибки());
<TAB>КонецПопытки;
```

Правильно:

```text
<TAB>Контрагент = Объект.Контрагент;
<TAB>Договор = Объект.Договор;
<TAB>
<TAB>Если ЗначениеЗаполнено(Договор) Тогда
<TAB><TAB>
<TAB><TAB>ЗаполнитьДоговор(Договор);
<TAB>КонецЕсли;
<TAB>
<TAB>Попытка
<TAB><TAB>
<TAB><TAB>ЗаписатьОбъект(Объект);
<TAB>Исключение
<TAB><TAB>
<TAB><TAB>Сообщить(ОписаниеОшибки());
<TAB>КонецПопытки;
```

Если тело внешнего блока сразу начинается с вложенного управляющего блока,
пустая строка перед вложенным блоком всё равно сохраняется на tab-уровне тела
внешнего блока.

Пустая строка без табуляции в этом месте тоже неверна:

```text
<TAB>Если ЗначениеЗаполнено(Объект) Тогда
<EMPTY>
<TAB><TAB>Если Объект.Проведен Тогда
```

Плохо:

```text
<TAB>Если ЗначениеЗаполнено(Объект) Тогда
<TAB><TAB>Если Объект.Проведен Тогда
<TAB><TAB><TAB>
<TAB><TAB><TAB>ОбработатьПроведенныйОбъект(Объект);
<TAB><TAB>КонецЕсли;
<TAB>КонецЕсли;
```

Правильно:

```text
<TAB>Если ЗначениеЗаполнено(Объект) Тогда
<TAB><TAB>
<TAB><TAB>Если Объект.Проведен Тогда
<TAB><TAB><TAB>
<TAB><TAB><TAB>ОбработатьПроведенныйОбъект(Объект);
<TAB><TAB>КонецЕсли;
<TAB>КонецЕсли;
```

## Пример визуальной геометрии блока

Менее удачно:

```text
Функция СоответствиеТоваровРеализациям(ВыборкаТоварыПоРеализациям)
<TAB>ВозвращаемоеЗначение = Новый Соответствие();
<TAB>
<TAB>Пока ВыборкаТоварыПоРеализациям.Следующий() Цикл
<TAB><TAB>ТоварыРеализации = Новый Массив();
<TAB><TAB>
<TAB><TAB>ВыборкаТовары = ВыборкаТоварыПоРеализациям.Выбрать();
<TAB><TAB>
<TAB><TAB>Пока ВыборкаТовары.Следующий() Цикл
<TAB><TAB><TAB><TAB>СтрокаТовары = Новый Структура();
<TAB><TAB><TAB><TAB>ЗаполнитьЗначенияСвойств(СтрокаТовары, ВыборкаТовары);
<TAB><TAB><TAB>
<TAB><TAB><TAB><TAB>ТоварыРеализации.Добавить(СтрокаТовары);
<TAB><TAB>КонецЦикла;
<TAB><TAB>
<TAB><TAB>ВозвращаемоеЗначение.Вставить(ВыборкаТоварыПоРеализациям.Реализация, ТоварыРеализации);
<TAB>КонецЦикла;
<TAB>
<TAB>Возврат ВозвращаемоеЗначение;
КонецФункции
```

Лучше:

```text
Функция СоответствиеТоваровРеализациям(ВыборкаТоварыПоРеализациям)
<TAB>ВозвращаемоеЗначение = Новый Соответствие();
<TAB>
<TAB>Пока ВыборкаТоварыПоРеализациям.Следующий() Цикл
<TAB><TAB>ТоварыРеализации = Новый Массив();
<TAB><TAB>
<TAB><TAB>ВыборкаТовары = ВыборкаТоварыПоРеализациям.Выбрать();
<TAB><TAB>
<TAB><TAB>Пока ВыборкаТовары.Следующий() Цикл
<TAB><TAB><TAB>СтрокаТовары = Новый Структура();
<TAB><TAB><TAB>ЗаполнитьЗначенияСвойств(СтрокаТовары, ВыборкаТовары);
<TAB><TAB><TAB>
<TAB><TAB><TAB>ТоварыРеализации.Добавить(СтрокаТовары);
<TAB><TAB>КонецЦикла;
<TAB><TAB>
<TAB><TAB>ВозвращаемоеЗначение.Вставить(ВыборкаТоварыПоРеализациям.Реализация, ТоварыРеализации);
<TAB>КонецЦикла;
<TAB>
<TAB>Возврат ВозвращаемоеЗначение;
КонецФункции
```

Во втором варианте внутренний блок образует цельную колонку на направляющих
IDE: все sibling-операторы стоят на одном уровне, а пустая строка не ломает
ритм уровня.
