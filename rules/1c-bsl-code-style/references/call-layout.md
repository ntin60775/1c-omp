# Layout вызовов и сигнатур

Этот файл решает только форму записи вызовов, сигнатур и выражений. Он не
решает, какой API вызывать.

## Вызовы

### Когда одна строка

Держите вызов в одну строку, если:

- 1-2 аргумента, все тривиальные;
- строка помещается в 140 символов;
- вызов читается как один атомарный шаг.

```bsl
СтрокаJSON(Данные)
СсылкаJSON(Ссылка, Наименование)
ДатаISO(Дата)
```

### Когда многострочно

Раскрывайте многострочно, если:

- 3+ значимых аргумента;
- строка не помещается в 140 символов;
- аргументы сами являются стадиями или вычисляются отдельно;
- есть вложенный вызов, условное выражение или длинный литерал;
- нужно видеть каждый аргумент при review.

Каждый аргумент на своей строке, закрывающая скобка на отдельной строке:

```bsl
НовыйМетод = ОписаниеМетода(
    "timesheet",
    "V1",
    1,
    "РХ: Табель учета рабочего времени за период",
    "Ответ = Преф_PAPIИнтеграция.Табель(...)"
);
```

Не превращайте layout-правку в изменение порядка вычислений или замену API.

## Сигнатуры

- Короткую сигнатуру (1-3 параметра) оставляйте в одну строку.
- Длинную сигнатуру раскрывайте вертикально, если она хуже читается или
  выходит за 140 символов.
- Не раскрывайте сигнатуру механически только потому, что параметров несколько.

## Тернарный оператор

Однострочная форма — только если весь тернарный помещается в 140 символов:

```bsl
Представление = ?(ЗначениеЗаполнено(Ссылка), Ссылка.Наименование, "");
```

Многострочная форма — если тернарный длинный или ветки имеют самостоятельный
смысл. Условие на первой строке, ветки на следующих:

```bsl
КодВремени = ?(ОписаниеВидаВремени = Неопределено,
    "",
    ОписаниеВидаВремени.Код
);
```

Закрывающая скобка `)` на отдельной строке, на уровне присваивания.
