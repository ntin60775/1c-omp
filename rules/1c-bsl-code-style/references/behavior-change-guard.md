# Защита от поведенческих изменений

Этот файл обязателен для style-review реального BSL-кода.

## Контракт

Стилевая правка не меняет поведение. Если правка меняет runtime contract, это
уже отдельное замечание по поведению с явным обоснованием, а не "улучшение
формы".

## Нельзя делать молча

- удалять или ослаблять защитное условие перед разыменованием ссылки, объекта,
  строки табличной части или значения внешнего контракта;
- заменять безопасное присваивание вида `Если ЗначениеЗаполнено(Источник) Тогда
  Приемник.Поле = Источник.Реквизит; КонецЕсли;` на прямое разыменование без
  доказанного инварианта заполненности;
- менять порядок fallback-веток: поиск по регистру, поиск по GUID/XML,
  создание нового объекта;
- переносить создание объекта раньше или позже, если это меняет default state,
  дату, владельца, заполнение реквизитов или побочные эффекты;
- менять источник даты: `ТекущаяДата()`, `ТекущаяДатаСеанса()`, дата из XML,
  дата документа;
- заменять API платформы, БСП или конфигурации на другой API без проверки
  сигнатуры и локальных аналогов применения;
- удалять условное заполнение реквизита только потому, что выражение стало
  короче;
- менять текст исключения, логирования или условие отката транзакции как часть
  форматирования.

## Разрешено

- переименовать локальную переменную без изменения значения;
- вынести сложное выражение в переменную с тем же значением;
- раскрыть или свернуть вызов без изменения порядка вычисления аргументов;
- заменить самописный код на платформенный/БСП API только как отдельную
  behavior-правку с доказанной применимостью.

## Обязательный self-check

Перед завершением сравните diff и ответьте:

- изменились ли условия `Если` вокруг присваивания или разыменования;
- изменился ли вызываемый метод или набор аргументов;
- изменился ли момент создания объекта;
- изменился ли источник default-значения;
- исчез ли fallback или защитное условие.

Если ответ "да", вынесите это как отдельное замечание по поведению или
верните исходное защитное условие.
