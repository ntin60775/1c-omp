# Заголовки функций и процедур

## Правило глубины документирования

Глубина doc comment зависит от видимости, но типизирующее описание параметров
— общее требование, независимое от видимости:

| Видимость | Аннотация |
|---|---|
| **Экспорт** | Полная |
| **Внутренний, очевидный** | Может отсутствовать — всё очевидно из названия |
| **Внутренний, неочевидный** | Содержательная (почему метод отдельный) |

У любого метода, который получает параметры или возвращает значение,
типизирующее описание (`Параметры:` / `Возвращаемое значение:`) обязательно —
независимо от видимости. Экспортный метод — публичный контракт: потребитель
видит только сигнатуру и doc comment, тело не читает. Внутренний метод —
деталь реализации: читатель смотрит сигнатуру и тело. Но блоки типов — это
часть сигнатуры, а не «шум»: они фиксируют контракт входных данных и
результата. Аннотация служебному методу не нужна, если всё очевидно из
названия. Процедура без параметров и без возвращаемого значения не требует
блоков `Параметры:` / `Возвращаемое значение:`.

## Когда аннотация не нужна

Если имя метода полностью объясняет его роль и нет неявных особенностей,
допустима однострочная форма:

```bsl
// Аннотация не требуется.
//
// Параметры:
//   ДанныеТабелей - Массив - набор табелей за период;
//   ДатаНачала - Дата - начало периода;
//   ДатаОкончания - Дата - конец периода.
//
// Возвращаемое значение:
//   Структура - ответ для JSON (meta + data).
//
Функция ПредставлениеТабелей(ДанныеТабелей, ДатаНачала, ДатаОкончания)
```

Или просто однострочная аннотация, если она добавляет контекст:

```bsl
// Модель табелей -> структура ответа (meta + data) для JSON.
//
// Параметры:
//   ДанныеТабелей - Массив - набор табелей за период;
//   ДатаНачала - Дата - начало периода;
//   ДатаОкончания - Дата - конец периода.
//
// Возвращаемое значение:
//   Структура - ответ для JSON (meta + data).
//
Функция ПредставлениеТабелей(ДанныеТабелей, ДатаНачала, ДатаОкончания)
```

Выбор между ними — на вкус автора. Главное — не дублировать имя метода
и не писать шаблонный текст без смысла.

## Когда нужна содержательная аннотация

Аннотация нужна, если без неё по имени метода неочевидны:

- контракт на границе внешнего обмена или формат выходных данных;
- важный побочный эффект;
- допущения и ограничения;
- необычная нормализация;
- отличие от похожего соседнего метода;
- причина, по которой метод вообще выделен отдельно.

Хорошая первая строка объясняет именно это отличие, а не пересказывает имя.

Пример:

```bsl
// Строгий разбор обязательного параметра-даты (YYYY-MM-DD).
// При ошибке возвращает Неопределено и заполняет ОписаниеОшибки.
//
// Параметры:
//   ПараметрыЗапроса - Структура - query-параметры запроса;
//   ИмяПараметра - Строка - имя обязательного параметра-даты;
//   ОписаниеОшибки - Строка - заполняется текстом ошибки.
//
// Возвращаемое значение:
//   Дата, Неопределено - разобранная дата; Неопределено при ошибке.
//
Функция ПараметрДата(ПараметрыЗапроса, ИмяПараметра, ОписаниеОшибки)
```

Имя `ПараметрДата` не говорит о побочном эффекте (заполнение `ОписаниеОшибки`)
и о том, что дата должна быть строго `YYYY-MM-DD` — аннотация это раскрывает.

## Что нельзя оставлять в финальном коде

- `//TODO: <Описание функции>`
- `<Параметр1>`, `<Тип.Вид>`, `<описание параметра>`
- заголовок, который описывает другой метод
- описание возвращаемого значения, не совпадающее с реальным return-contract
- фразы вида `Подготавливает данные для соответствующего этапа выгрузки.`, если
  они не помогают отличить один метод от другого

## Правила для параметров и возвращаемого значения (все методы)

1. Описывайте реальную семантическую роль параметра в текущем методе.
2. Если параметр является контейнером результата, пишите это явно.
3. Если функция возвращает представление для внешнего контракта, структуру данных обмена или нормализованное значение,
   это надо назвать прямо.
4. Если функция может вернуть пустое значение по умолчанию, это полезно отметить
   в блоке возвращаемого значения.
5. Если тип составной и схема стабильна, не дублируйте явное описание в
   потребителе: ссылайтесь на `ФункцияКонструктор`.
6. Если текущий метод сам является `ФункцияКонструктор`, документируйте поля,
   колонки и вложенные типы прямо в его блоке `Параметры:` или
   `Возвращаемое значение:`.
7. Если важное пояснение относится к конкретному параметру или возвращаемому
   значению, оно должно жить именно в блоке `Параметры:` или
   `Возвращаемое значение:`, а не в отдельном комментарии после сигнатуры
   метода или внутри тела.
8. Если имя параметра сохранено ради совместимости, а фактическая семантика уже
   другая, это нужно явно раскрывать в строке описания параметра.
9. В русском документирующем комментарии не оставляйте нерасшифрованный
   внутренний жаргон вроде `stub`, если его можно заменить точным русским
   описанием совместимости или роли параметра.

## Предпочтительные шаблоны

### Экспортный метод

```bsl
// Эндпойнт GET /hs/papi/V1/timesheet.
// Данные проведенных табелей учета рабочего времени за период.
//
// Параметры:
//   ПараметрыЗапроса - Структура - query-параметры запроса:
//     dateFrom, dateTo - Строка - YYYY-MM-DD, обязательные;
//     organization - Строка - GUID организации, опционально.
//
// Возвращаемое значение:
//   Структура:
//     * КодHTTP - Число - код ответа (200, 400);
//     * Тело - Строка - JSON тела ответа.
//
Функция Табель(ПараметрыЗапроса) Экспорт
```

### Внутренний метод (очевидный)

```bsl
// Модель табелей -> структура ответа (meta + data) для JSON.
//
// Параметры:
//   ДанныеТабелей - Массив - набор табелей за период;
//   ДатаНачала - Дата - начало периода;
//   ДатаОкончания - Дата - конец периода.
//
// Возвращаемое значение:
//   Структура - ответ для JSON (meta + data).
//
Функция ПредставлениеТабелей(ДанныеТабелей, ДатаНачала, ДатаОкончания)
```

### Внутренний метод (неочевидный)

```bsl
// Строгий разбор даты из строки YYYY-MM-DD. Ошибка -> Неопределено.
//
// Параметры:
//   СтрокаДаты - Строка - дата в формате YYYY-MM-DD.
//
// Возвращаемое значение:
//   Дата, Неопределено - разобранная дата; Неопределено при ошибке.
//
Функция ДатаИзСтроки(Знач СтрокаДаты)
```

### Внутренний метод (утилита)

```bsl
// Дата -> "YYYY-MM-DD".
//
// Параметры:
//   Дата - Дата - дата для форматирования.
//
// Возвращаемое значение:
//   Строка - дата в формате YYYY-MM-DD.
//
Функция ДатаISO(Знач Дата)
```

### Экспортный метод (конструктор)

```bsl
// Аннотация не требуется.
//
// Возвращаемое значение:
//  Структура:
//   * АдресСервиса - Строка - адрес конечной точки API.
//   * Таймаут - Число - таймаут подключения в секундах.
//
Функция ПараметрыПодключенияКAPI()
```
