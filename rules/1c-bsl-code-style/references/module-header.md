# Шапка модуля и верхний уровень файла

Этот файл задает отдельный слой проверки верхнего уровня файла для
`1c-bsl-code-style`.

Он нужен, когда review затрагивает не только тело методов, но и верх модуля:

- шапку модуля;
- стартовые комментарии;
- первую область;
- общий структурный проход по `*.bsl`.

## Когда читать

- при любом review реального BSL-модуля целиком;
- когда пользователь показывает замечание по шапке модуля;
- когда меняется верхний комментарий файла;
- когда нужно понять, корректно ли начинается модуль до первой `#Область`.

## Главное правило

Для review реального модуля недостаточно прохода только по методам.

Перед анализом процедур и функций нужно отдельно проверить верхний уровень
файла:

1. есть ли шапка модуля;
2. оформлена ли она как завершенный заголовочный блок;
3. не сломан ли переход от шапки к первой области;
4. читается ли модуль сверху вниз как файл, а не только как набор методов.

## Что считать корректной шапкой

Если модуль использует шапку с разделительными строками из `////////////////////////////////////////////////////////////////////////////////`,
она должна быть оформлена как замкнутый симметричный блок:

- верхняя линия;
- пустая строка-комментарий после верхней линии;
- одна или несколько строк описания;
- пустая строка-комментарий перед нижней линией;
- нижняя линия.

Плохо:

```bsl
////////////////////////////////////////////////////////////////////////////////
// Модуль содержит ...
// Используется совместно с ...
//

#Область ПрограммныйИнтерфейс
```

Лучше:

```bsl
////////////////////////////////////////////////////////////////////////////////
//
// Модуль содержит ...
// Используется совместно с ...
//
////////////////////////////////////////////////////////////////////////////////

#Область ПрограммныйИнтерфейс
```

Для рабочего контура этого навыка шапка модуля обязательна в каждом реальном
`*.bsl`-модуле. Отсутствие шапки считается дефектом верхней структуры файла.
Неполная шапка без внутренних пустых строк-комментариев сверху и снизу
описания тоже считается дефектом формы.
Этот reference задает только форму шапки; достаточность и точность описания
нужно подбирать по смыслу конкретного модуля.

## Как проверять верхний уровень файла

Перед review методов ответьте на вопросы:

1. Первая смысловая конструкция файла оформлена как законченный блок верхнего уровня?
2. Есть ли внутри шапки пустая строка-комментарий после верхней линии и перед нижней?
3. Отделена ли шапка от первой области ровно настолько, чтобы переход был
   читаемым и предсказуемым?
4. Нет ли смешения: шапка выглядит как заголовок модуля, а фактически
   обрывается перед первой областью?

## Граница с `v8std`

Этот reference не подменяет формальный стандарт `#std455`.

Его задача — сделать структурный проход по верхнему уровню файла обязательной
частью style-review:

- `v8std` отвечает, есть ли формальное нарушение структуры модуля;
- текущий reference отвечает, что агент не имеет права пропустить шапку
  модуля только потому, что дальше в файле есть более срочные дефекты на уровне
  методов.

## Практическое правило для рабочего контура агента

Если review идёт по реальному `*.bsl`-модулю, начинайте с короткого порядка:

1. шапка модуля;
2. первая область и верхняя структура файла;
3. только потом методы и локальная форма внутри них.

Иначе легко получить ложное чувство, что модуль "починен",
хотя верхний уровень файла остался дефектным.
