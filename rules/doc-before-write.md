# Сверка перед записью (причина A постмортема тикета 09)

Все три отказа загрузки и оба провала смоука тикета 09 — один паттерн:
строгий конфигуратор/платформа использовался как валидатор вместо
предварительной сверки имени/механизма по источнику, доступному в один
вызов. Ни одна сверка не была дорогой; дорогой была каждая итерация
загрузки.

## Правило

ПЕРЕД записью любого имени или механизма в исходник 1С (через
`unica.code.patch`, `unica.form.compile`, `unica.meta.add`,
`unica.dcs.compile`, `unica.runtime.execute build/load` и др.) — сверься
с источником. Один вызов:

| Что сверяется | Источник |
|---|---|
| Имя реквизита, ресурса регистра, измерения | `unica.meta.info` |
| Имя свойства СКД, `DataPath` панели настроек | `unica.dcs.info` + эталонная форма (`unica.form.info` / `read`) |
| Функция языка запросов, сериализация XSD | `unica.documentation.search` / `unica.standards.search` |
| Существующий паттерн (обработка пустой ссылки и т.п.) | `unica.code.search` / `unica.code.definition` / `read` по `src/` |
| Содержимое ресурса | `unica.source.read` |

## Платформенные утверждения — из документации

**Память не источник.** Ни одно утверждение о возможностях платформы — где
допустимо объявлять переменные, какие типы и методы существуют, как
инициализируются параметры сеанса, что делает блокировка или транзакция, какой
API доступен в каком контексте, — не принимается «по памяти». Источник —
`unica.documentation.search` → `unica.documentation.get` (documentId) либо
`unica.standards.search` / `explain`; версию платформы для запроса передавать
явно (см. `unica-mcp`).

Инварианты:

- **Перед проектированием механизма — сверка** (механизм = хранение состояния,
  доступ к данным, события, блокировки, транзакции, фоновые задания, обмен,
  инициализация). В отчёте — `documentId` источника, на который опирается
  решение.
- **Исходники не заменяют документацию**: `read`/`grep` по `src/**`,
  `meta.info`, `code.search` отвечают на «как сделано здесь», а не на «что
  вообще допустимо платформой». Пустой результат поиска сверкой не считается.
- **Сверка адресна**: она нужна по тому API, чьи аргументы или порядок вызовов
  меняются. Гейт проверяет факт сверки, а не её адресность — «сверка была» ≠
  «метод проверен».
- **При расхождении памяти и документации права документация** — перечитать
  доку, а не спорить.
- **Документация молчит → это gap, а не повод угадать**: назвать пробел,
  проверить фактом на контуре, записать в KB. До проверки утверждение помечать
  словами «догадка»/«не проверено» — в коде и в KB. Если тикет требует
  невозможного платформенно — это дефект тикета, решение по документации с
  согласованием.
- **Проверка платформенных утверждений входит в задачу ревьюера** наравне с
  кодом и доками проекта.

## Что не видит поиск: модули обычных форм

Модуль обычной формы платформа выгружает не текстом, а внутри контейнера
`Ext/Form.bin`: его не видят ни `git-grep`, ни bsl-анализаторы, ни
`unica.code.search` — «проверено по исходникам» для такой части кодовой базы
нуждается в явном способе. Вынимать модули `.bsl` внутрь `src/` бессмысленно —
следующая полная выгрузка сотрёт их. Читать — экстракцией во **внешний**
каталог (проектный скрипт/скилл, результат вне source-set), и результат такой
вычитки не заменяет документацию по возможностям платформы.

## MUST NOT

- Писать имена «по памяти» или из шаблона без сверки.
- Передавать в строгий конфигуратор непроверенные имена как валидатор:
  каждая итерация загрузки дорога.
- Угадывать `DataPath` панели настроек: канон — `ReportStructure`
  (в `UseAlways` эталонной формы и в док-сёрче), не `Settings.Group` /
  `Settings.Structure`.
- Вставлять `<condition>` в Template.xml голой строкой без проверки
  сериализации по XSD/референсу.

## Детерминированный слой

Хук `doc-gate.ts` блокирует мутирующие вызовы Unica, если в сессии не
было ни одной сверки (documentation/meta/dcs/form/code/source-инструменты
или `read`/`grep` по `src/`). Гейт считает факт, не адресность, и он же
сбрасывает флаг после мутации метаданных; bash-грепы сверкой не считаются.
