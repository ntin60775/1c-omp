# Тестовые фикстуры: сверка с метаданными и паттернами (пункт 1 постмортема тикета 10)

Фикстуры тикета 10 — это BDD-модули в `tests/cfe/Тесты/CommonModules/`
и `.feature`-файлы. Три факапа одного класса:

- **A1**: `ОбъектГруппы.ЭтоГруппа = Истина` в фикстуре — системный
  реквизит нередактируем («Поле объекта недоступно для записи»). Паттерн
  «группа = обычный элемент» был в тикете 04 — не посмотрел.
- **C1b**: опечатка в имени ресурса в запросе фикстуры — имя не скопировано
  из метаданных, а набрано по памяти.
- **C1**: после перехода UI на другую организацию серверная фикстура
  осталась на первой — рассинхрон двух половин сценария.

## Правило

### 1. Имена реквизитов/ресурсов — только из метаданных

ПЕРЕД записью имени реквизита, ресурса регистра, измерения в фикстуру —
скопировать точное имя из метаданных:

```
unica.meta.info { "metadataPath": "<адрес объекта>", "cwd": "<корень>" }
```

Не писать по памяти. Опечатка в имени ресурса = падение прогона
(«Поле не найдено»).

### 2. Системные реквизиты не редактируются

`ЭтоГруппа`, `ПометкаУдаления`, `Ссылка`, `ВерсияДанных` и другие
системные реквизиты — **нередактируемы**. Попытка присвоить им значение
в фикстуре = «Поле объекта недоступно для записи».

Для создания группы справочника — использовать штатный механизм
(паттерн из предыдущих тикетов), а не присваивать `ЭтоГруппа`.

### 3. Паттерны — из предыдущих тикетов и соседних фикстур

ПЕРЕД написанием новой фикстуры — посмотреть:
- как аналогичная задача решена в фикстурах предыдущих тикетов
  (`unica.code.search` по `tests/cfe/Тесты/`);
- соседние фикстуры того же типа.

Не писать «по наитию», если паттерн уже существует.

### 4. Синхронизация двух половин сценария

Если сценарий меняет одну половину (например, организацию в UI), —
синхронизировать вторую (серверную фикстуру). После правки фикстуры
или шага — проверить, что обе половины сценария ссылаются на одни и те
же данные.

### 5. Фикстура идемпотентна и «саморемонтируется»

Прогон может быть прерван, и его данные остаются в базе. Найденный тестовый
объект **достраивается** до пригодного состояния, а не пересоздаётся; создание —
«лучшее усилие»: если данных нет и создать нельзя, состояние не меняется, а
решение принимает вызывающий код (пропуск или падение). Без `Попытка`,
которая молчит о причине.

Почему это важно: соседние наборы берут «первое по ссылке» подходящее значение,
поэтому оставленный прежним прогоном неполный объект становится их входом — и
падают уже чужие тесты. Поломка всплывёт не там, где создана.

### 6. Фикстура пишет только свои объекты

Признак «своего» — префикс фикстуры в наименовании. Найденные объекты **без**
префикса — только чтение: достраивать и править их нельзя, даже если тест из-за
них падает. Проверка префикса — часть кода фикстуры, а не соглашение на словах.

## Детерминированный слой

`unica.meta.info` засчитывается хуком `doc-gate.ts` как сверка.
Запись в фикстуры через `unica.code.patch` гейтится тем же хуком.

## MUST NOT

- Писать имена реквизитов/ресурсов в фикстурах по памяти.
- Присваивать значения системным реквизитам (`ЭтоГруппа` и др.).
- Игнорировать существующие паттерны предыдущих тикетов.
- Менять одну половину сценария без синхронизации второй.
- Пересоздавать найденный неполный тестовый объект вместо достройки.
- Править или достраивать объекты без префикса фикстуры.
