# 1c-omp

omp-плагин контура 1С-разработки: правила, хуки-гейты и навыки развёртывания.
Ставится **на уровень проекта** — только в те проекты, где есть 1С.

## Зависимость: Unica

Плагин **не работает сам по себе**: вся работа с 1С идёт через Unica MCP
(`unica.*`), а это отдельный плагин третьей стороны из чужого маркетплейса —
`IngvarConsulting/unica-marketplace`. Он несёт MCP-сервер, закреплённый рантайм
(там же лежит `v8-runner`) и 76 предметных навыков.

Механизма зависимостей в каталоге omp нет, поэтому связь обеспечивается
навыком развёртывания: он проверяет наличие `unica@unica`, при отсутствии —
добавляет маркетплейс и ставит плагин. Без Unica правила и хуки этого плагина
бессмысленны: они требуют `mcp__unica__*` и не опускаются до прямого
редактирования исходников.

Установка контура — **двухфазная**, и это не формальность: после установки
навыки подхватываются `/reload-plugins`, а MCP-сервер и хуки-расширения —
только **перезапуском сессии**. До перезапуска `unica.*` в сессии не существует.

## Состав

| Путь | Что |
|---|---|
| `rules/1c-platform.md` | sticky-блоки платформы (`alwaysApply`): приоритет Unica, источник по платформе, версия из `v8project.local.yaml`, запрет полной синтакс-проверки |
| `rules/1c-bsl-code-style.md` + `references/` + `profiles/` + `scripts/` | стиль BSL: правило, 10 справочников, 2 профиля, исполняемый чекер `bsl_style_check.py` |
| `rules/1c-bsl-style-on-edit.md` | TTSR-напоминание при правке `.bsl` |
| `rules/unica-source-gate.md` | исходники 1С правятся только через Unica MCP |
| `rules/standards-check.md` | проверка по стандартам 1С после правки |
| `rules/doc-before-write.md` | сверка имён и механизмов с источником до записи |
| `rules/verify-after-create.md` | полный валидационный набор после создания объекта |
| `rules/test-contour.md` | тестовый контур: раннер, грабли прогонов, мониторы |
| `rules/vanessa-tests.md` | шаги и фичи Vanessa — только по официальной документации |
| `rules/test-fixtures.md` | фикстуры: имена реквизитов только из метаданных |
| `rules/worktree-env.md` | инициализация воркспейса Unica в ворктри |
| `rules/retry-discipline.md` | после двух одинаковых падений — стоп и диагностика |
| `rules/ship-1c.md` | opt-in: `/ship` в 1С-проекте всегда останавливается до коммита |
| `extensions/unica-gate.ts` | гейт исходников: блокирует правку мимо Unica, следит за `fullRebuild` расширений и за воркспейсом ворктри |
| `extensions/doc-gate.ts` | блокирует мутирующие вызовы Unica без предварительной сверки |
| `extensions/retry-gate.ts` | дисциплина ретраев |
| `skills/1c-project-bootstrap/` | развёртывание контура в проекте: маркетплейсы, Unica, структура, `v8project.*`, тестовый контур |
| `skills/unica-project-setup/` | настройка Unica под проект: MCP без дублей, `v8project.yaml` руками, секреты в local-overlay, первая выгрузка |
| `skills/unica-test-contour/` | YAxUnit и Vanessa на живой ИБ |

Хуки объявлены в `package.json` → `omp.extensions`: это extension-модули
(используют `HookAPI`), а не декларативные `hooks/pre|post`.

## Чего здесь нет

- **KB и dev-flow** — это плагин `ontoship`, предметно-независимый: он ставится
  в любой проект, не только 1С.
- **Машинные правила** (безопасность, accessibility, identity) — уровень машины,
  репозиторий `sot-omp-core`, доставляется скриптом, а не плагином.
- **Специфики конкретных проектов** — имён баз, учёток, объектов и путей здесь
  нет и быть не должно. Проектная конкретика живёт в самом проекте, файлами с
  именами, **не совпадающими** с плагинными: одноимённый файл перекрывает
  плагинное правило целиком и навсегда отключает его обновление.

## Установка

```bash
omp plugin marketplace add IngvarConsulting/unica-marketplace   # один раз на машине
omp plugin marketplace add ntin60775/sot-omp-marketplace        # один раз на машине
omp plugin install --scope project unica@unica
omp plugin install --scope project 1c@sot-omp-marketplace
# перезапустить сессию: MCP и хуки поднимаются только при старте
```

Проверка после перезапуска:

```json
unica.project.status { "cwd": "<корень проекта>" }
```

`ready: true` и список source-set'ов — контур жив.

## Обновление

Релиз = тег в этом репозитории + bump `ref` и `version` в записи каталога.
Дальше в проектах `omp plugin upgrade 1c@sot-omp-marketplace`.
