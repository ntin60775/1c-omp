# 1c-omp — вход для агента

Плагин контура 1С-разработки. Ставится в проект и работает только вместе с
Unica MCP — без него правила и хуки бессмысленны.

## Что знать до правки

- **Специфики проектов здесь быть не должно.** Ни имён баз, ни учёток, ни
  объектов, ни путей. Всё зависящее от проекта читается из `v8project.yaml` /
  `v8project.local.yaml` либо живёт в самом проекте отдельным файлом.
- **Хуки — это код.** `extensions/*.ts` объявлены в `package.json` →
  `omp.extensions`. После правки проверяй, что модуль грузится.
- **`alwaysApply: true` — это цена.** Такое правило уезжает в системный промпт
  каждой сессии; раздувать его нельзя без причины.
- **Файла `rules/RULES.md` здесь нет намеренно.** Это имя всегда перекрывается
  sticky-файлом из `~/.omp/agent/` (native-провайдер, приоритет 100 против 90
  у плагина), поэтому платформенные блоки лежат в `rules/1c-platform.md`.

## Проверка перед коммитом

```bash
# 1. Ни одного имени чужого проекта, базы, учётки или объекта.
#    Сами имена — в .forbidden-names.txt (gitignored, одна строка = grep-паттерн):
#    в публичном репозитории им не место, а гейт без конкретных имён бесполезен.
PAT=$(cat .forbidden-names.txt 2>/dev/null)
[ -z "$PAT" ] && echo 'НЕТ .forbidden-names.txt — заведи его, проверка не выполнена' \
  || (grep -rnE "$PAT" --include='*.md' --include='*.ts' --include='*.py' . \
        --exclude-dir=.git --exclude='.forbidden-names.txt' \
      && echo 'НАЙДЕНО — править' || echo 'чисто')

# 2. Поведение хука и замка: модули грузятся, логика совпадает с ожиданием
bun run tests/ib-lock.test.ts      # замок на инфобазу
bun run tests/unica-gate.test.ts   # хук: гейты и замок
```

## Связанные репозитории

- `sot-omp-marketplace` — каталог, из которого плагин ставится.
- `sot-omp-core` — машинный слой (identity, безопасность), **приватный**:
  доставляется скриптом, а не плагином. Для этого плагина не обязателен.
- `ontoship-omp` — KB и dev-flow; предметно-независим, ставится в любой проект.
